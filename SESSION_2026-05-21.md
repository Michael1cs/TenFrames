### Voice queue: clear between problems
After fixing module-level voice serialization in the previous session,
two new symptoms showed up where the queue still chained the PREVIOUS
problem's instruction onto the new problem's voices.

**Symptom 1 (Adventure, Farm Share):** "după prima provocare la sfârșit
repetă ce spune la începutul provocării". When the child solved problem
0 quickly, the `share_intro` clip was still mid-play. Then problem 1's
voices queued behind it, so the kid heard the end of problem 0's intro
before the new problem started.

**Fix:** call `voice.stop()` inside the scheduled voice action in
`AdventureLevelScreen` right before the new action fires — clears any
leftover audio from the previous problem in the same screen.

**Symptom 2 (Free Play, addition/subtraction):** "apare vocea anterioară
cu provocarea înainte de a începe provocarea nouă". Same root cause —
`pre_have_<theme>_<n1>` from problem 0 could still be queued or playing
when problem 1's voices got enqueued.

**Fix:** in `GameShell`'s per-problem `useEffect`, call `voice.stop()`
before the new `queueVoice(pre_have…)` / `queueVoice(instr_…)` calls.
Skipped on the very first problem of a session so the welcome isn't
clipped. Praise from the previous correct answer (post_great_*) might
get cut if it's still queued at the moment the new problem voice fires
— acceptable tradeoff vs hearing the wrong instruction.
